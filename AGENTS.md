# AGENTS.md — правила написания кода в melpops

Договорённость о **том, как** писать код в этом проекте. Если изменение делает
код меньше и понятнее без потери корректности — оно правильное.

## Базовые принципы

- **Явный, типизированный, тестируемый.** Аннотации на каждом аргументе и
  возвращаемом значении. `Any` запрещён: смоделируйте реальную форму
  (Pydantic-модель, `TypedDict`, союз).
- **Pydantic — контракт.** Вход и выход функций описываются Pydantic-моделями
  из `src/schemas.py`. Схема — это API: она тестируется.
- **Тонкие вьюхи.** Роут валидирует вход, вызывает сервис, возвращает схему.
  Бизнес-логики и SQL в роутах нет.
- **Явная инъекция зависимостей.** Всё, что нужно функции, — её аргумент.
  Скрытых глобальных состояний нет.
- **Самое простое решение побеждает**, даже если существующий паттерн
  более «продвинутый».

## Жёсткие запреты

- **Нет флагов-булев**, меняющих поведение функции: лучше две функции, чем
  одна с `if flag`.
- **Один `try` = одна потенциально падающая строка.** Никогда не оборачивать
  несколько операций в один `try`.
- **Нет `# type: ignore`** без обсуждения.
- **Нет мёртвого кода** в коммитах.
- **Нет секционных комментариев-разделителей** (`# ───────`) в Python.

## Обработка ошибок

Конкретное сообщение, причина всегда передаётся:

```python
try:
    result = await connection.fetchval("SELECT 1")
except PostgresError as exc:
    raise RuntimeError("Postgres недоступен") from exc
```

Ошибки, уходящие наружу (в health-отчёт, в HTTP-ответ), — стабильный
контракт: машинночитаемый статус + человекочитаемое сообщение. Технические
детали — только в лог.

## Слои

```
src/api/      — роуты: тонкие вьюхи, FastAPI
src/services/ — бизнес-логика: функции, Pydantic в → Pydantic из
src/          — точка сборки, конфиг, логирование, контракты (schemas.py)
tests/        — тесты: pytest, httpx, один сценарий — одно имя
```

## Тестирование

- Тестируется всё: функции, сервисы, роуты, схемы.
- Тесты быстрые и изолированные: внешние зависимости (БД, сеть) в тестах
  недоступны детерминированно (см. `tests/conftest.py`).
- Имя теста описывает сценарий: `test_health_report_degraded_when_postgres_unavailable`.

## Инструменты

- **Всегда `uv run`** для python/pytest/ruff — никогда не голый `python`.
- Lint: `uv run ruff check .`, формат: `uv run ruff format .`, тесты: `uv run pytest -q`.
- Оба ruff-прохода должны быть чистыми в затронутых файлах.
- Изменения хирургией: стиль как у соседей, diff минимальный,
  не трогать то, о чём не просили.

## Конвенции

- `exceptions` — исключения, `schemas.py` — Pydantic-контракты,
  `models.py` — только ORM-модели БД. Не смешивать.
- Docstring: Google-стиль, краткий императив («Вернуть», «Проверить»).
  Типы — в сигнатуре, не в docstring.
- Логи: `logging.getLogger(__name__)`, формат выставляет `setup_logging`.
  Запрос — один `request_id`, все логи запроса связаны.
